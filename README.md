# عُدّة المهندس

موقع عربي مجاني ثابت يضم 67 أداة هندسية لطلاب الهندسة والفنيين، مع حل خطوة بخطوة لكل أداة.

**الموقع:** https://motaz-inshasi.github.io/engineering-tools-ar/

## المبادئ

- HTML و CSS و JavaScript فقط، بلا خادم ولا قاعدة بيانات ولا خطوة بناء.
- بلا حسابات ولا كوكيز ولا تحليلات.
- كل الروابط نسبية، فيعمل الموقع من أي مسار فرعي مثل `/repo-name/` على GitHub Pages.
- المكتبات الخارجية منسوخة محلياً في `vendor/` بإصدارات مثبتة.

## هيكل المشروع

| المسار | المحتوى |
|---|---|
| `index.html` | الصفحة الرئيسية مع البحث في كل الأدوات |
| `category/<التصنيف>/` | صفحة لكل تصنيف |
| `tools/<الأداة>/` | صفحة لكل أداة |
| `assets/css/` | التنسيقات المشتركة |
| `assets/js/` | دوال الواجهة المشتركة وسجل الأدوات `registry.js` |
| `lib/` | وحدات الحساب الصافية (ES modules بلا DOM)، تستخدمها الصفحات والاختبارات |
| `vendor/` | المكتبات الخارجية المثبتة |
| `tests/unit/` | اختبارات الوحدات بـ node:test |
| `tests/browser/` | اختبارات المتصفح بـ Playwright |
| `tests/site/` | فحص الروابط و SEO والعمل من مسار فرعي |
| `scripts/` | خادم محلي ومولّد sitemap |
| `site.config.json` | اسم الموقع والنطاق وإعدادات الإعلانات (معطلة) |

## التشغيل محلياً

```bash
npm install
npm run serve
```

ثم افتح `http://localhost:8080/`. ولتجربة المسار الفرعي كما في GitHub Pages:

```bash
node scripts/serve.mjs --base /test-repo/
```

## توليد الصفحات

صفحات HTML تُكتب مسبقاً من `assets/js/registry.js` وبيانات `meta` في كل وحدة داخل `lib/`. بعد أي تعديل:

```bash
npm run generate
```

الملفات الناتجة تُحفظ في المستودع، فالموقع يعمل كما هو بلا خطوة بناء عند النشر.

## الاختبارات

```bash
npm test
```

يشغّل بالترتيب:
- `npm run test:unit`: اختبارات الوحدات والتحققات المستقلة.
- `npm run test:site`: فحص الروابط و SEO والمسار الفرعي.
- `npm run test:browser`: اختبارات Playwright على Chrome المثبت، بعرض الهاتف والحاسوب، مع لقطات شاشة في `tests/screenshots/`.

## إضافة أداة جديدة

1. أضف سطراً في `assets/js/registry.js` فيه `slug` (اسم إنجليزي قصير) و `category` و `title`.
2. أنشئ `lib/<التصنيف>/<slug>.js` يصدّر:
   - `meta`: الوصف، والقوانين بصيغة LaTeX، والمدخلات، والمثال المحلول مع النص المتوقع، ومثالاً لمدخلات خاطئة.
   - `solve(input)`: تُرجع `results` و `steps`، ويمكن أن تُرجع `blocks` للجداول والرسوم. يُستخدم `fail(رسالة، حقل)` للأخطاء.
3. أنشئ `tests/unit/<التصنيف>/<slug>.test.js` فيه 5 تحققات على الأقل، أولها `checkExample(mod)`.
4. شغّل `npm run generate` ثم `npm test`. اختبارات المتصفح والموقع تشمل الأداة الجديدة تلقائياً.

أسهل طريقة: انسخ أداة مشابهة (مثل `lib/dc-circuits/ohms-law.js`) وعدّلها.

## نشر التعديلات

بعد نجاح `npm test`:

```bash
git add -A
git commit -m "وصف التعديل"
git push
```

يعيد GitHub Pages النشر تلقائياً خلال دقيقة أو اثنتين. لاختبار الموقع الحي:

```bash
LIVE_URL=https://motaz-inshasi.github.io/engineering-tools-ar/ npx playwright test
```

## زر التبرع (مخفي)

زر «ادعم الموقع» في أعلى كل صفحة يفتح صفحة `support/`، وفيها:
- عنوان محفظة USDT على شبكة TRC20؛
- رمز QR؛
- زر نسخ؛
- خطوات التبرع من Binance.

الإعدادات في `site.config.json` تحت `donate`:

| الحقل | المعنى |
|---|---|
| `enabled` | `false` يخفي الزر والصفحة تماماً؛ `true` يظهرهما |
| `usdtTrc20` | عنوان محفظة USDT على شبكة TRON. يُتحقق من صحته (checksum) عند التوليد، فلا يُنشر عنوان فيه خطأ مطبعي |
| `binancePayId` | معرّف Binance Pay (اختياري، أرقام فقط) |
| `url` | رابط تبرع خارجي إضافي (اختياري، يبدأ بـ `https://`) |
| `label` و `text` | نص الزر، والجملة التوضيحية |

بعد أي تعديل: `npm run generate` ثم `npm test` ثم انشر التعديل.

تنبيه: العنوان يظهر في ملف الإعدادات داخل المستودع العام بمجرد رفعه، حتى لو كان الزر مخفياً.

## الإعلانات (معطلة)

في `site.config.json` يوجد خيار `ads.enabled: false`. عند تفعيله يضع المولّد أماكن فارغة للإعلانات فقط، ولا يضيف أي سكربت.
